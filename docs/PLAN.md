## Что сделано

- **Дизайн:** главная (десктоп и мобильная), карточка товара, дизайн-система.
- **Стек:** Nuxt 4, Tailwind 4, TypeScript, i18n, `@nuxt/image`, `@nuxtjs/sitemap`, `@nuxtjs/robots`, `nuxt-schema-org`. Шрифты из npm-пакетов: Google Fonts из песочницы недоступны.
- **Главная:** слайдер-баннер (3 слайда, автопрокрутка с индикатором, свайп, клавиатура, пауза при наведении), бегущая лента, карусель букетов, блок «Букет від флориста» с формой, шаги заказа, отзывы, FAQ, плавающие кнопки.
- **Анимации:** появление блоков при прокрутке (`v-reveal`, `app/plugins/reveal.ts`; без JS контент виден, `prefers-reduced-motion` учтён), плавающие лепестки, hover-эффекты, прогресс прокрутки в шапке, сжимающаяся шапка.
- **Три студии:** Київ, Бориспіль, Щасливе — страницы `/studios/*`, секция на главной, контакты в подвале, JSON-LD `Florist` для каждой, ссылки на Instagram и Telegram.
- **Telegram:** `tools/sync-telegram.mjs` читает публичные каналы `t.me/s/<канал>` (посты, фото, телефоны из описания). Парсер покрыт тестом (`npm run test:telegram`). Синк запускается в GitHub Actions перед каждой сборкой и каждые 6 часов; при ошибке сети остаются прежние данные.
- **Instagram:** ручной файл `app/data/instagram.json`. Парсинг страниц Instagram не используется: нарушает правила сервиса.
- **Иллюстрации:** SVG-композиции, генерируются скриптом `tools/gen-art.mjs` (временные, до фотосъёмки). Иконка цветка 🌸 — `app/components/FlowerIcon.vue`.
- **Деплой:** GitHub Pages через `.github/workflows/pages.yml`; сайт работает на подпути `/kvitkova-feya/` (`useAsset()`); запасной вариант — `netlify.toml`.

## Отличия от исходного ТЗ

- Вместо Next.js/Astro выбран **Nuxt 4** (решение заказчика).
- Каталог и контент пока **статические файлы** в репозитории, без headless CMS.
- Добавлены **три студии** со своими страницами (в ТЗ была одна студия).
- Контакты берутся из **Telegram-каналов**; Instagram — вручную.
- Сайт публикуется с ветки `feat/nuxt-scaffold`, а не из `main`.
- Репозиторий **публичный**: так требует бесплатный GitHub Pages.

## Что осталось (по приоритету)

1. **Заявки:** серверная часть отправки в Telegram-бота и на почту, защита Cloudflare Turnstile, передача бюджета и студии в заявку. Для статического хостинга нужна внешняя функция (Cloudflare Worker, Netlify Function и т. п.).
2. **Реальные данные:** цены (добавить `Offer` в разметку товара), тексты, отзывы, адреса и часы студий, зоны доставки, ссылки мессенджеров.
3. **Фото:** заменить SVG-иллюстрации на съёмку; фото для блока Instagram.
4. **Ветки:** влить `feat/nuxt-scaffold` в `main`, сделать `main` основной веткой деплоя.
5. **Домен:** свой домен, `NUXT_PUBLIC_SITE_URL`, брендированные OG-изображения, `robots.txt`, `FAQPage` после написания ответов.
6. **Страницы по ТЗ:** поводы с SEO-текстами, «Весілля та події», «Для бізнесу», «Доставка і оплата», политика конфиденциальности, блог, своя страница 404.
7. **Аналитика и согласие на cookie:** GA4/GTM, Meta Pixel, Consent Mode v2.
8. **CMS:** Keystatic или Sanity, чтобы менять каталог без разработчика.
9. **Качество:** Lighthouse и axe на реальном домене, уменьшение тяжёлых SVG (коробка ≈ 180 КБ).

## Как работать с проектом

```bash
npm install
npm run dev              # разработка
npm run generate         # статическая сборка в .output/public
npm run sync:telegram    # подтянуть посты из Telegram-каналов
npm run test:telegram    # проверка парсера
node tools/gen-art.mjs public   # пересоздать SVG-иллюстрации
```

- Студии и контакты: `app/data/studios.json`; Instagram-лента: `app/data/instagram.json`; тексты: `i18n/locales/*.json`.
- Публикация: пуш в `main` или `feat/nuxt-scaffold` запускает workflow «Deploy to GitHub Pages». Для запуска вручную — Actions → Run workflow. Если ветка не `main`, добавьте её в Settings → Environments → github-pages → Deployment branches.
